**创建日期**: 2026-04-19
**状态**: 设计完成，待实现
**目标**: 为校招面试创建技术亮点可视化展示页面

## 1. 页面定位与目标

### 1.1 页面目的
- 展示AI旅行助手项目的核心技术亮点
- 通过对比式展示突出改进效果
- 用量化数据支撑技术方案价值
- 面向校招面试官，快速传递项目技术深度

### 1.2 页面路由
- 路径: `/showcase`
- 文件: `frontend/app/showcase/page.tsx`
- 独立路由，不干扰现有应用功能

### 1.3 展示策略
- **不包含**: Hero区、项目简介、技术栈列表、时间线等背景信息
- **核心聚焦**: 技术亮点 + 量化效果
- **展示方式**: Before vs After对比 + 数据表格

## 3. Section详细设计

### 3.1 Section 1: 提示词工程与意图识别

#### 3.1.1 对比区内容

**左侧 - 问题痛点（淡红背景）**:
```
• 提示词硬编码难维护
• 注入攻击风险高
• 长对话易超Token限
• 纯LLM意图分类成本高、响应慢
```

**右侧 - 解决方案（淡绿背景）**:
```
• 提示词模板管道架构，支持热更新
• 意图-模板动态映射
• 「缓存→关键词→LLM」三级意图分类器
• 缓存优先策略，80%+高频查询前置覆盖
```

#### 3.1.2 架构流程图

**三级意图分类流程**:
```
用户输入 → [缓存层检查] → [关键词匹配] → [LLM意图分类]
           ↓命中          ↓匹配          ↓兜底
          直接返回       模板选择       深度理解
```

**实现要点**:
- 用横向流程图展示
- 每个节点用方框表示
- 箭头标注命中/匹配/兜底三种路径
- 简洁明了，避免复杂细节

#### 3.1.3 量化对比表格

| 指标 | Before | After | 提升 |
|------|--------|-------|------|
| 意图准确率 | ~70% | **90%** | +20% |
| LLM调用次数 | 100%查询 | 40%查询 | **-60%** |
| 响应速度 | 2-3秒 | <0.5秒 | 5x提升 |

**表格样式**:
- 核心数字 **90%** 和 **-60%** 用蓝色加粗高亮
- 表头行用灰色背景
- 数值列居中对齐

### 3.2 Section 2: 三级记忆架构

#### 3.2.1 对比区内容

**左侧 - 问题痛点（淡红背景）**:
```
• 用户偏好不持久记忆
• 推荐同质化严重
• 无法实现千人千面
• 跨会话信息丢失
```

**右侧 - 解决方案（淡绿背景）**:
```
• 工作记忆层（会话级）
• 情景记忆层（跨会话）
• 语义记忆层（长期持久）
• 自动晋升机制
• ChromaDB向量检索支持
```

#### 3.2.2 记忆层级示意图

**三层堆叠式结构**:
```
┌────────────┐
│ 工作记忆    │ ← 当前会话即时上下文
│ Working    │   高频访问，易丢失
├────────────┤
│ 情景记忆    │ ← 跨会话偏好沉淀
│ Episodic   │   高置信度自动晋升
├────────────┤
│ 语义记忆    │ ← ChromaDB长期存储
│ Semantic   │   向量检索，千人千面
└────────────┘
      ↑
    自动晋升机制
```

**实现要点**:
- 用堆叠方框展示（上层易丢失，下层最持久）
- 每层标注：英文术语 + 中文说明 + 特性
- 底部向上箭头表示晋升机制
- 不同层可用不同深浅颜色区分（如从上到下颜色加深）

#### 3.2.3 量化对比表格

| 指标 | Before | After | 提升 |
|------|--------|-------|------|
| 用户偏好记忆准确率 | 0% | **88%** | +88% |
| 推荐个性化度 | 低 | 高 | 显著提升 |
| 跨会话记忆 | 无 | 有 | 实现持久 |

**表格样式**:
- 核心数字 **88%** 用蓝色加粗高亮
- "显著提升"和"实现持久"可用绿色文字强调

### 3.3 Section 3: 长对话上下文压缩

#### 3.3.1 对比区内容

**左侧 - 问题痛点（淡红背景）**:
```
• 长对话Token超限
• 对话频繁中断
• 调用成本高昂
• 用户体验差
```

**右侧 - 解决方案（淡绿背景）**:
```
• 前置清理（冗余去除）
• 推理时守卫（阈值监控）
• 后置压缩（分级策略）
• 流式兜底（分批处理）
```

#### 3.3.2 压缩策略流程图

**四层防护机制（竖向流程）**:
```
用户输入
   ↓
┌───────────┐
│ 前置清理   │ ← 去除重复、无意义对话
│ Layer 1   │
└───────────┘
   ↓
┌───────────┐
│ 推理时守卫 │ ← Token超阈值时拦截
│ Layer 2   │
└───────────┘
   ↓
┌───────────┐
│ 后置压缩   │ ← 三级压缩：摘要→关键信息→核心词
│ Layer 3   │
└───────────┘
   ↓
┌───────────┐
│ 流式兜底   │ ← 超长对话分批处理，避免中断
│ Layer 4   │
└───────────┘
   ↓
正常响应
```

**实现要点**:
- 竖向流程图，每层独立方框
- 每层标注Layer编号和作用
- Layer 3需特别标注三级压缩强度
- 流程箭头清晰连接各层

#### 3.3.3 量化对比表格

| 指标 | Before | After | 提升 |
|------|--------|-------|------|
| Token成本 | 100% | 55% | **-45%+** |
| 对话中断率 | 频繁中断 | **0中断** | 完全解决 |
| 长对话支持 | ~50轮 | **无限轮** | 体验提升 |
| 响应稳定性 | 低 | 高 | 显著改善 |

**表格样式**:
- 核心数字 **-45%+** 用蓝色加粗高亮
- **0中断** 和 **无限轮** 用绿色加粗强调（突出彻底解决的卖点）

## 7. 设计决策记录

### 7.1 为什么不包含Hero区？
**决策**: 直接展示技术内容，无项目简介铺垫
**理由**:
- 面试官时间有限，快速切入核心更有价值
- 技术亮点本身已包含足够上下文
- 项目背景可在口头介绍时补充

### 7.2 为什么选择对比式展示？
**决策**: Before vs After对比 + 量化表格
**理由**:
- 对比展示直观突出改进效果
- 面试官容易理解"解决了什么问题"
- 数据支撑增强说服力

### 7.3 为什么量化指标分散在各section？
**决策**: 每个section包含自己的量化表格
**理由**:
- 形成"问题→方案→效果"完整闭环
- 数据与技术方案直接关联，逻辑清晰
- 避免"孤立数据展示"缺少上下文

### 7.4 为什么选择单页滚动式布局？
**决策**: 长页面依次展示，无Tab或分页
**理由**:
- 面试场景需要完整浏览，适合滚动
- 避免面试官错过某个Tab内容
- 移动端友好（可滚动查看）

### 7.5 为什么不使用动态动画？
**决策**: 静态展示，无动画效果
**理由**:
- 技术展示需要专业感，避免花哨
- 加载速度快，面试场景网络可能不稳定
- 内容清晰易读，不受动画干扰
