🛡️ 上下文管理系统架构
阶段1
推理前
• 前置清理
• TTL检查
• 软修剪
• 上下文占用>30%
阶段2
推理时
• 工具执行守卫
• 单条工具>50%拒绝
• 预算预留25%
• 替换最旧工具结果
阶段3
推理后
• 后置压缩
• 窗口占比>75%触发
• LLM摘要生成
• 流式兜底
↓ 用户消息 → LLM推理 → 响应输出 ↓
🧹 前置清理（推理前）
• 保护范围：倒数第3条助手消息之后的所有工具结果
• TTL检查：清理时长超过TTL的工具消息
• 软修剪：单条工具>4000字符，保留首尾各1500字符
• 替换指示：中间部分用"...trimmed..."指示
• 保护策略：user/system消息不受清理
• 比例控制：上下文占用>30%时执行软修剪
• 超限处理：占用>50%，工具消息替换为占位符
✓ 清理对象：仅工具结果
✓ 保护消息：user/system
✓ 软修剪：保留首尾+指示符
🛡️ 工具执行守卫（推理时）
• 单条限制：工具结果占比>50%，拒绝添加
• 预算预留：总预算预留25%给LLM回答内容
• 防止压缩：避免添加后立即触发后置压缩
• 替换策略：最旧工具结果→摘要→占位符
• 拒绝机制：超预算时拒绝添加新工具结果
⚠️ 防止工具结果挤占LLM回答空间
⚠️ 单条工具不得超过50%窗口
🗜️ 后置压缩（推理后）
• 触发条件：窗口占比>75%
• 消息分离：确保系统消息不被压缩
• 压缩对象：仅压缩对话历史
• 多块分块：基础分块40%，最小15%，最近20%不压缩
• LLM摘要：每块消息用LLM生成摘要
• 降级策略：3次失败后降级为计数摘要
• 规则重注：检查并重新注入规则消息
📋 系统消息受保护，仅压缩历史对话
🌊 流式兜底（输出中）
• 80%警告：提前告知用户回复较长，已精简展示
• 100%截断：返回已生成内容，避免空白页
• 用户提示：告知用户已到达最大轮数限制
• 用户体验：始终有返回结果，不显示空白
✓ 80%窗口：友好提示
✓ 100%窗口：返回内容非空白
✓ 用户体验：始终有返回结果
📊 上下文窗口管理
• 最大窗口：128K tokens（DeepSeek模型）
• 安全阈值：75%时触发压缩，确保25%缓冲
• 消息优先级：system > user > assistant > tool
• 时间优先级：最近消息 > 历史消息
• Token估算：实时监控上下文占用比例
